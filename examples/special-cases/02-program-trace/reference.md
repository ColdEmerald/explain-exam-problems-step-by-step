# 参考输出：02 编程题的逐行执行跟踪

> 人工审定的基准输出。核心是四轮循环的变量变化必须逐一列出。

## 题型判断与考点

**题型**：代码执行结果预测 + 逐行跟踪。

**直接考点**：Python `for` 循环、`range` 的左闭右开语义、`if/else` 分支、`%=` 与累加/累减。

**隐含考点**：
- `range(1, 5)` **不含** 5，因此循环执行 4 次（$i=1,2,3,4$）——这是最常见的读错点；
- `total` 在两个分支中被**不同地修改**，必须按实际走向逐步追踪，不能只记最终公式；
- `i % 2 == 0` 判定的是**偶数**，奇数走 else 分支。

**常用公式**：`range(start, stop)` 生成 $start, start+1, \dots, stop-1$。

**命题人想考察什么**：能否把「读代码」变成「逐步模拟执行」，而不是凭经验猜一个答案。

## 第一眼突破口

**看到的第一样东西**：`for i in range(1, 5)`。

**由此联想到什么**：这是**左闭右开**区间，$i$ 依次取 $1,2,3,4$，共 4 轮，**不含 5**。

**关键的第二层观察**：`total` 在两个分支里的操作不同——偶数轮做 `total += i*i`（加平方），奇数轮做 `total -= i`（减本身）。所以必须**按轮次顺序**追踪，不能提取统一公式。

**因此选择的路线**：逐轮模拟，每轮列出 $i$ 的值、走的分支、`total` 的变化，最后给出输出。

## 逐步推导

### 第一步：确定循环范围

**做什么**：明确 $i$ 的取值序列与循环次数。

**依据**：`range(1, 5)` 生成从 1 开始、到 5 之前（不含 5）的整数序列。

**结论**：$i = 1, 2, 3, 4$，循环体执行 **4 次**。

### 第二步：确定初始状态

**做什么**：记录进入循环前的变量值。

**依据**：代码第一行 `total = 0`。

**初始状态**：`total = 0`，`i` 未定义（循环变量）。

### 第三步：第 1 轮（$i=1$）

**做什么**：判断分支并更新 `total`。

**依据**：`if i % 2 == 0` 判定偶数。$1 \% 2 = 1 \neq 0$，条件为假，走 `else` 分支。

**执行**：`total -= i` ⟹ `total = 0 - 1 = -1`

**本轮结束状态**：`i = 1`，`total = -1`

### 第四步：第 2 轮（$i=2$）

**依据**：$2 \% 2 = 0$，条件为真，走 `if` 分支。

**执行**：`total += i * i` ⟹ `total = -1 + 2\times 2 = -1 + 4 = 3`

**本轮结束状态**：`i = 2`，`total = 3`

### 第五步：第 3 轮（$i=3$）

**依据**：$3 \% 2 = 1 \neq 0$，走 `else` 分支。

**执行**：`total -= i` ⟹ `total = 3 - 3 = 0`

**本轮结束状态**：`i = 3`，`total = 0`

### 第六步：第 4 轮（$i=4$）

**依据**：$4 \% 2 = 0$，走 `if` 分支。

**执行**：`total += i * i` ⟹ `total = 0 + 4\times 4 = 0 + 16 = 16`

**本轮结束状态**：`i = 4`，`total = 16`

### 第七步：循环结束后的输出

**做什么**：读出 `print` 的内容。

**依据**：循环结束后 `total = 16`，`print(total)` 输出其值。

**输出**：

```
16
```

**变量变化汇总表**：

| 轮次 | $i$ | $i \% 2$ | 走的分支 | 执行的语句 | `total` 变化 | 轮末 `total` |
|---|---|---|---|---|---|---|
| 初始 | — | — | — | `total = 0` | — | 0 |
| 1 | 1 | 1 | else | `total -= i` | $0-1$ | $-1$ |
| 2 | 2 | 0 | if | `total += i*i` | $-1+4$ | 3 |
| 3 | 3 | 1 | else | `total -= i` | $3-3$ | 0 |
| 4 | 4 | 0 | if | `total += i*i` | $0+16$ | 16 |

### 第八步：验算

**验算 1 — 用闭式公式独立核对**：偶数轮贡献 $+i^2$（$i=2,4$），奇数轮贡献 $-i$（$i=1,3$）：

$$
\text{total} = (-1 + 3) + (-2 + 16) = 2 + 14 = 16 \checkmark
$$

**验算 2 — 手工跑一遍 Python**：用 `python -c` 执行原代码，确认输出为 `16`。这一步可以把「我以为的语义」与「实际语义」对齐，尤其能暴露 `range` 与 `%` 的细节误解。

**验算 3 — 检查边界**：若误以为 `range(1,5)` 含 5，会多算一轮 $i=5$（奇数轮，`total -= 5`），得到 $16-5=11$。**11 与 16 的差距正是这个陷阱的识别标志**。

**验算通过。**

## 解题思维复盘

**从题目特征回到方法选择**：代码含分支与状态修改时，唯一可靠的方法是**逐轮模拟**，没有捷径。

**为什么不能靠「读一遍代码猜结果」**：因为 `total` 在两个分支中被不同地修改，而分支走向依赖 $i$ 的奇偶性。凭直觉容易漏掉某一轮或搞错分支归属。

**常见错误路线为什么走不通**：
- 把 `range(1, 5)` 当作含 5 —— 输出会是 11，是最主要的错误来源；
- 忘记 `i * i` 是**先乘后加**，把第 4 轮算成 `total += 4` —— 得到 8 之类的值；
- 认为 `total -= i` 是把 `total` 设为 $-i$ —— 实际是「原值减 $i$」。

## 核心套路总结

> **看到什么 → 想到什么 → 怎么做 → 检查什么**

**看到什么**：含循环与条件分支的短代码。

**想到什么**：先确定循环变量的**完整取值序列**（特别注意区间端点），再逐轮模拟。

**怎么做**：
1. 读出循环变量的取值序列与总轮数（Python 用 `range`，左闭右开）；
2. 记录初始变量值；
3. 逐轮：写出变量值 → 判断分支条件 → 写出该分支实际执行的语句（含运算优先级）→ 更新变量值；
4. 汇总成表格；
5. 读出最终输出；
6. 用闭式公式或实际执行做独立核对。

**检查什么**：轮数是否与 `range` 参数一致；每轮走的是哪个分支；复合运算的优先级；用另一种方式（闭式或实跑）核对结果。

## 易错点

1. **错误表现**：把 `range(1, 5)` 当作含 5，输出 11。
   **错误原因**：Python 的 `range` 是左闭右开。
   **避免方法**：先明确写出取值序列 $1,2,3,4$ 再逐轮。

2. **错误表现**：第 2、4 轮算成 `total += i` 而非 `total += i*i`。
   **错误原因**：漏看乘号。
   **避免方法**：逐轮写出**实际执行的语句**原文，再代入数值。

3. **错误表现**：某轮用错分支（把奇数轮当偶数）。
   **错误原因**：未逐轮判断 `i % 2`。
   **避免方法**：每轮都写出 `i % 2` 的值。

4. **错误表现**：只给最终答案，无过程。
   **错误原因**：把「读代码」当成普通计算题。
   **避免方法**：`SKILL.md` 要求编程题加入变量变化与执行顺序的跟踪，汇总表是标准形式。

5. **错误表现**：算完不核对。
   **错误原因**：小代码也可能算错，尤其在分支交替时。
   **避免方法**：用闭式公式或直接实跑核对一遍，成本极低。

## 更快捷的方法

**方法**：对这种「奇偶轮不同操作」的短循环，直接按轮次列表心算：奇数轮 $-1,-3$，偶数轮 $+4,+16$，合计 $(-1-3)+(4+16) = -4+20 = 16$。

**适用条件**：轮数少（$\le 5$）、分支条件简单。

**快在哪里**：省去表格。

**为什么成立**：每轮操作独立且只作用于 `total`，可直接累加。

**说明**：但**必须先确认轮数与分支归属**——本题的 11 与 16 之差正来自轮数误判。快捷法跳过表格不等于跳过思考。

## 同类型变式题

**变式题**：阅读以下代码，写出输出结果，并逐行说明变量变化：

```python
acc = []
for i in range(3):
    for j in range(i + 1):
        acc.append(i * 10 + j)
print(acc)
print(len(acc))
```

**它训练的识别点**：**嵌套循环**——外层 $i$ 变化时内层的**循环次数随 $i$ 改变**（`range(i+1)` 的上界是变量），这比单层循环多一个「状态变化」维度，恰好命中 `SKILL.md` 中「程序执行过程等时，明确列出范围或状态变化」这条规则。

**自测检查点**：先写出内层循环在每个 $i$ 下的执行次数：$i=0$ 时 1 次，$i=1$ 时 2 次，$i=2$ 时 3 次。

**最终答案**：

- $i=0$：$j=0$ ⟹ 追加 0
- $i=1$：$j=0,1$ ⟹ 追加 10、11
- $i=2$：$j=0,1,2$ ⟹ 追加 20、21、22

`acc = [0, 10, 11, 20, 21, 22]`，`len(acc) = 6`。

输出为：

```
[0, 10, 11, 20, 21, 22]
6
```

回复「讲解变式题」可看完整推导。
