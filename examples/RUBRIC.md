# 判定规则（Rubric）

本文件定义如何判定一次技能输出是否合格。判定分两层：

- **第一层：确定性检查**——由 `check.py` 自动完成，只看结构与事实，不看表达。
- **第二层：质量评分**——由人工或 LLM-as-judge 完成，看深度、语气与教学价值。

两层都通过才算该样本合格。**第一层不过，无需进入第二层。**

## 第一层：确定性检查

### 1.1 结构检查（required_sections / absent_sections）

固定讲解流程为 8 步，标准模式下以下标题**必须出现**：

| 章节标题 | 对应规则 |
|---|---|
| 题型判断 | 步骤 1 |
| 第一眼突破口 | 步骤 2 |
| 逐步推导 | 步骤 3 |
| 解题思维复盘 | 步骤 4 |
| 核心套路总结 | 步骤 5 |
| 易错点 | 步骤 6 |
| 更快捷的方法 | 步骤 7 |
| 同类型变式题 | 步骤 8 |

章节标题的匹配规则：

- 允许在标题前后附加编号、标点、修饰词（如 `### 2. 第一眼突破口：观察积分区间`）。
- 匹配时忽略大小写与 Markdown 装饰符（`#`、`*`、`**`）。
- 只要标题**包含**关键词即视为命中，例如 `### 2. 第一眼突破口` 命中 `第一眼突破口`。

例外：

- **简明模式**只要求 3 个章节：题型判断、逐步推导、最终答案。
- **图片歧义样本**（`special-cases/03-image-ambiguity`）进入 `pause` 模式，期望**不出现**推导类章节，改为出现不确定性清单。

### 1.2 关键词检查（required_keywords / forbidden_keywords）

- `required_keywords`：答案中必须出现的字面片段（如 `收敛域`、`分段`）。用于确认关键讨论没有缺席。
- `forbidden_keywords`：答案中不得出现的字面片段。统一禁用 `显然`、`容易得`、`同理可得`、`易知` —— 这四个词在 `SKILL.md` 中被明令禁止用于掩盖关键计算。

注意：关键词是**字面匹配**，不区分 LaTeX 与纯文本写法。因此关键词应选择与排版无关的词（如 `收敛域` 而非 `\mathrm{ROC}`）。

### 1.3 事实检查（key_facts / absent_facts）

- `key_facts`：每项提供 `any_of` 候选列表，只要命中其中**任意一种写法**即算通过。这用于容忍 LaTeX 与 ASCII 的表达差异，例如同一结论可写作 `1-e^{-t}`、`1 - e^(-t)` 或 `1-\exp(-t)`。
- `absent_facts`：必须**不出现**的内容。用于图片歧义样本——一旦答案里出现了具体结论，就说明模型没有执行暂停协议。

### 1.4 第一层通过标准

所有检查项全部通过。任一失败即判定该次输出**结构不合格**，不应进入人工评分。

## 第二层：质量评分

结构合格后，按五个维度各评 1–5 分。**每维必须有具体扣分理由**，不接受整体印象分。

### 维度 1：推导完整性（权重最高）

| 分 | 标准 |
|---|---|
| 5 | 每一步都写明「做什么、依据什么、目的」，无跳步；代数与符号变换逐步展开 |
| 4 | 推导完整，但个别简单步骤合并处理 |
| 3 | 存在 1–2 处跳步，关键转折处有展开 |
| 2 | 多处跳步，或仅给出结果链条而无中间依据 |
| 1 | 只有结论，无推导 |

### 维度 2：依据正确性

| 分 | 标准 |
|---|---|
| 5 | 引用的定义、公式、定理全部正确，且说明了适用条件 |
| 4 | 引用正确，个别公式未说明适用条件 |
| 3 | 引用基本正确，存在一处条件未交代 |
| 2 | 引用有误但结论侥幸正确 |
| 1 | 引用错误导致结论错误 |

### 维度 3：验算完备性

按学科选择适用项检查：定义域、收敛域、因果稳定性、单位、边界条件。

| 分 | 标准 |
|---|---|
| 5 | 全部适用项均已检查，且检查过程可复核 |
| 4 | 主要适用项已检查，遗漏次要项 |
| 3 | 只做了回代验算，未检查收敛域/定义域等 |
| 2 | 仅口头声称「已验算」而无实际过程 |
| 1 | 完全未验算 |

### 维度 4：教学价值

考察「为什么这样想」是否讲清，而非只给算式。

| 分 | 标准 |
|---|---|
| 5 | 第一眼突破口说明了「由题目特征联想到某方法」的推理链；套路总结可迁移 |
| 4 | 突破口指出了方向，但未充分解释联想依据 |
| 3 | 有套路总结但流于复述计算过程 |
| 2 | 仅罗列步骤，缺少思路解释 |
| 1 | 纯答案堆砌 |

### 维度 5：表达质量

| 分 | 标准 |
|---|---|
| 5 | 因果句充分（「因为…所以…」）；公式排版清晰；最终答案醒目 |
| 4 | 表达通顺，个别句子因果关系不明确 |
| 3 | 可读但偏干；公式排版偶有混用 |
| 2 | 多处堆砌术语而无因果说明 |
| 1 | 表述混乱，读者难以跟随 |

### 第二层通过标准

**维度 1（推导完整性）与维度 2（依据正确性）任一低于 3 分即整体不合格**，其余维度不得低于 2 分。

## LLM-as-judge 提示词模板

用于自动化第二层评分时，将下列内容作为评判指令，并把 `input.md` 与待评输出一并提供：

```text
你是一位严格的研究生课程助教，正在评估一份「考研式逐步讲题」技能的实际输出。

参考标准：
- 结构合格：包含题型判断、第一眼突破口、逐步推导、解题思维复盘、核心套路总结、
  易错点、更快捷的方法、同类型变式题 这 8 个章节。
- 推导必须写明「做什么、依据什么、为什么此时想到它」，不得用「显然」「容易得」「同理可得」掩盖。
- 关键结论必须正确，验算项按学科选择：定义域 / 收敛域 / 因果稳定条件 / 单位 / 边界条件。
- 语气为耐心严谨的考研辅导，先讲人话再给术语，多用具体因果句。

待评输出：
<OUTPUT>

请按以下五个维度分别给 1–5 分，并为每一维写出具体的扣分理由（引用输出中的原句，
说明它哪里不达标）。不要给笼统的整体印象评价。

1. 推导完整性
2. 依据正确性
3. 验算完备性
4. 教学价值
5. 表达质量

最后给出：
- 结构是否合格（是/否）
- 维度 1 或维度 2 是否低于 3 分（是/否）
- 总体结论：合格 / 不合格

若判定不合格，请指出最需要修改的一处具体位置。
```

## 修改 SKILL.md 后的标准回归流程

1. 拉取最新 `SKILL.md`，对每个样本生成一次输出。
2. 运行 `check.py --all --outputs-dir ./outputs`，记录第一层失败项。
3. 对第一层通过的样本运行 judge 评分，记录维度 1/2 的分数变化。
4. 若出现维度 1 或 2 低于 3 分的新增失败，**不得合入**——先定位是哪一节规则改动导致的。
5. Tier A 样本若因措辞调整导致 `reference.md` 与新输出差异明显，更新参考输出并记入变更日志。
